Headless Schema Synthesis

Traditional API discovery requires engineers to write swagger files manually or hope API providers keep documentation up to date. SarembokVE automatically reverse-engineers target services in real time by deploying a sandboxed headless Chromium browser that observes network payloads, DOM interactions, forms, and client bundles.

How It Works

  1. Sandboxed Navigation: The Playwright container loads the requested URL in an ephemeral Chromium profile with memory and CPU boundaries.
  2. Network & DOM Interception: Outgoing fetch and XHR calls, form structures, and JSON payloads are inspected and recorded.
  3. Schema Induction: The Specification Engine maps inferred primitives, nested objects, and arrays into standard JSON Schema draft 2020-12 representations.
  4. Format Synthesis: The raw schema is compiled into an OpenAPI 3.1 JSON document and an idiomatic TypeScript .d.ts contract interface.

OpenAPI 3.1 & TypeScript Exports

Every generated specification can be downloaded directly from the browser or fetched programmatically via standard curl commands.

# Download verified OpenAPI 3.1 JSON specification
curl -sLO "https://sarembok.com/api/spec/export?target=https://httpbin.org&format=openapi"

# Download type-safe TypeScript interfaces
curl -sLO "https://sarembok.com/api/spec/export?target=https://httpbin.org&format=typescript"

CI/CD Pipeline Integration

Integrate SarembokVE directly into GitHub Actions or GitLab CI to fail pull requests whenever an upstream dependency or internal endpoint changes without an updated contract:

name: API Drift Detection Gate
on: [pull_request]

jobs:
  audit-contract:
    runs-on: ubuntu-latest
    steps:
      - name: Audit Target API with SarembokVE
        run: |
          SPEC=$(curl -sf "https://sarembok.com/api/spec?target=https://api.staging.internal")
          VERIFIED=$(echo "$SPEC" | jq -r '.verified')
          if [ "$VERIFIED" != "true" ]; then
            echo "API Verification Failed!"
            exit 1
          fi
          echo "Verified in $(echo "$SPEC" | jq -r '.latencyMs')ms"

1-Click Sovereign GPU Worker Mesh

To eliminate reliance on expensive commercial cloud APIs (OpenAI, Anthropic), SarembokVE supports decentralized worker clustering. Any machine with a CUDA-enabled GPU (including free Google Colab T4 or A100 instances) can join the cluster in seconds.

Launching a Colab Worker

# Inside a Google Colab notebook (GPU Runtime):
!curl -sSL https://sarembok.com/Deployment/cloud/colab_worker.py -o colab_worker.py
!python colab_worker.py --server wss://sarembok.com/worker/ws --models qwen-2.5-coder-32b,qwen-2.5-coder-7b

Once registered, the central SarembokVE runtime automatically routes inference tasks to your connected sovereign worker over encrypted WebSockets, prioritizing zero-cost local compute.

Headless REST API Reference

The public REST API provides fast, scriptable access for automated tools and CI runners without browser session overhead.

Endpoint: GET /api/spec

Query Parameters:

  • target (required): Fully qualified URL to inspect (e.g., https://httpbin.org).

  "target": "https://httpbin.org",

    "openapi": "3.1.0",
